# 줄 번호(`#`) 칸 행 선택 — 클릭·드래그·Shift·Ctrl

**날짜:** 2026-10-22
**릴리스:** v1.0.4

요청은 세 번에 걸쳐 늘었다. 처음에는 "행 왼쪽 `#`을 클릭하면 한 행 전체 선택"이었고,
이어서 데이터(표) 모드에도 넣고 선택된 행의 `#` 칸 색을 바꾸기로 했으며, 마지막으로
드래그·Shift·Ctrl을 더했다.

---

## 1. 동작

| 조작 | 텍스트 모드 | 데이터 모드 |
|---|---|---|
| 클릭 | 그 줄 전체를 **개행까지** 선택 | 그 행의 모든 컬럼 |
| 드래그 | 여러 줄(위·아래 모두) | 여러 행 |
| Shift+클릭 | 앵커 줄부터 클릭한 줄까지 | 같음 |
| Ctrl+클릭 | 떨어진 줄을 하나씩 담기/빼기 | 같음 |

- 선택에 걸친 행의 `#` 칸은 선택된 컬럼 헤더와 같은 파랑 배경(`header_sel_color`) +
  진한 글자로 칠한다(`paint_line_number_cell(.., selected)`).
- 드래그가 본문 위·아래로 나가면 세로 자동 스크롤(`edge_autoscroll`, 텍스트 모드 드래그와
  같은 양). 가로는 밀지 않는다 — 포인터가 텍스트 열 왼쪽(`#` 칸)에 있으니 가로까지 보면
  계속 왼쪽으로 굴러간다.
- 편집 모드에서만 동작한다. 뷰 모드에는 원래 선택이 없다.

## 2. 설계

### 개행까지 선택 (`gutter_text_sel`)

텍스트 모드 한 줄 선택은 `(L,0)`–`(L+1,0)`이다. VS Code·EmEditor와 같다 — 복사하면
개행까지 들어가고, 그대로 타이핑하면 줄이 통째로 바뀐다. 마지막 줄은 개행이 없으니
`(L,len)`까지. 텍스트 안 트리플클릭은 지금처럼 개행 없이 줄 내용만 고른다.

위로 끌면 앵커가 아래 줄 끝, 캐럿이 위 줄 첫 칸에 오도록 뒤집는다. Shift+화살표로
이어서 늘릴 때 방향이 맞는다.

### 드래그 래치와 Ctrl

`gutter_drag_active`는 `cell_drag_active`/`text_drag_active`와 같은 래치다. `#` 칸에서
누름이 시작되면 켜지고 버튼을 떼면 꺼진다. 드래그 중 끝 행은 포인터 **높이만** 보고
정한다(`gutter_pointer_y` → `gutter_row_hit`). 포인터가 옆 본문으로 나가도 행 선택이
이어진다.

Ctrl 누름도 래치를 켠다. 안 켜면 버튼을 누르고 있는 다음 프레임에 같은 줄이 또 눌린
것으로 보여, 넣었다 뺐다를 되풀이한다. 대신 `gutter_sel`을 비워 끌어도 넓어지지 않게 했다.

### Shift 앵커 (`gutter_shift_anchor`)

`gutter_sel`에 `#` 칸으로 만든 (앵커, 끝)을 남긴다. Shift+클릭 때 **지금 선택이 그 값으로
만든 선택과 같을 때만** 그 앵커를 잇는다. 그 사이 셀이나 텍스트를 클릭해 선택이 바뀌었으면
그 선택의 앵커 행을 쓴다. 상태를 따로 무효화하는 코드를 여러 곳에 흩뿌리지 않고, 쓰는
순간 한 번 대조하는 방식이다.

### Ctrl로 고른 행 (`picked_rows`)

기존 선택(`text_sel`, `cell_sel`)은 연속 구간 하나라 떨어진 행을 담을 수 없다. 그래서
`Document::picked_rows: BTreeSet<usize>`를 따로 두었다.

- 비어 있지 않으면 이것이 곧 선택이고, 그동안 `text_sel`/`cell_sel`은 None이다.
- 다른 선택이 생기면(찾기·전체 선택·Shift+화살표·셀 클릭 등 어디서든) 렌더 시작에서
  비운다. "둘이 같이 있으면 고른 뒤에 다른 선택이 생긴 것"이라는 규칙 하나로 처리해,
  선택을 만드는 모든 지점을 찾아다니지 않는다.
- 드래그로 고른 구간이 있는 상태에서 Ctrl+클릭하면 그 구간을 먼저 담는다(엑셀과 같음,
  `toggle_picked_row`의 `seed`).

고른 행에 대한 동작:

| | 텍스트 모드 (`apply_picked_text_intent`) | 데이터 모드 (`apply_picked_cell_action`) |
|---|---|---|
| 복사 | 줄마다 개행을 붙여 이어 붙임 | 행마다 TSV, 줄바꿈으로 이음 |
| 잘라내기 | 복사 + 줄 삭제 | 복사 + 셀 내용 비우기(사각 선택의 잘라내기와 같음) |
| Delete / Backspace | 줄 삭제 | 셀 내용 비우기 |
| 행 삭제(메뉴) | — | 행 삭제 |
| 붙여넣기·행 삽입 | 고른 줄을 풀고 평소 경로 | 첫 고른 행을 행 선택으로 바꾸고 평소 경로 |
| 타이핑·이동 | 고른 줄을 풀고 평소 경로 | — |

떨어진 여러 곳에 동시에 타이핑하는 기능은 만들지 않았다.

### 떨어진 행 삭제의 되돌리기 (`delete_picked_rows`)

연속 구간마다 `ReinsertRemoved`를 만들어 `Batch` 하나로 묶는다. Ctrl+Z 한 번에 전부
돌아온다.

- 구간은 **오름차순**으로 담는다. `Batch`는 담긴 순서대로 적용되므로, 앞 구간이 먼저
  되살아나야 뒤 구간의 원래 인덱스가 맞는다.
- 지우기는 뒤에서부터 한다(인덱스가 밀리지 않게).
- 전부 지우면 `remove_row`가 빈 줄 하나를 남기므로, 되돌릴 때 그 줄을 먼저 치운다
  (`RemoveInserted { at: 0, count: 1 }`). 기존 `DeleteRows`와 같은 이유다.

## 3. 테스트

추가 6개(전체 890개 통과).

- 순수 함수: `gutter_text_sel_covers_newline_and_flips_upward`,
  `toggle_picked_row_seeds_from_row_selection_then_toggles`,
  `gutter_shift_anchor_prefers_gutter_anchor_only_when_unchanged`,
  `delete_picked_rows_undoes_in_one_step`(떨어진 행·전부 삭제 둘 다 되돌리기 확인)
- 통합(실제 `egui::Context`로 프레임을 돌리고 포인터 이벤트를 넣는다):
  `text_gutter_drag_shift_and_ctrl_pick`, `table_gutter_selects_rows_and_ctrl_picks`
- 처음 넣은 `text_line_number_click_selects_whole_line`(한 줄·마지막 줄)도 유지.

**프로브.** 기능을 끄고 돌려 실패하는지 확인했다.
- 클릭 처리를 끄면 → "줄 번호 클릭으로 선택이 생겨야 한다"로 실패.
- 드래그 끝 행 판정을 끄면 → 두 통합 테스트가 "한 줄만 선택됨"으로 실패.
- Ctrl 분기를 끄면 → 두 통합 테스트가 "고른 행 없음"으로 실패.

`#` 칸 색이 바뀌는지는 자동 테스트로 확인하지 못했다.

## 4. 남은 것

- Ctrl+드래그로 구간을 하나 더 담는 기능은 없다(Ctrl+클릭은 한 행씩).
- 뷰 모드(큰 파일)에서는 동작하지 않는다 — 셀 선택 자체가 편집 모드 기능이다.

## 작업 중 걸린 것

- **테스트 하네스의 수정 키.** Shift/Ctrl 테스트가 "그냥 클릭"처럼 동작해 실패했다. egui는
  수정 키 상태를 이벤트(`PointerButton.modifiers`)가 아니라 `RawInput::modifiers`에서 읽는다.
  실제 앱은 winit이 채우므로 하네스(`gutter_frame_mod`)만 고쳤다.
- **bash heredoc.** 따옴표가 섞인 Python 편집 스크립트를 heredoc으로 넘기다 bash가 깨졌다.
  스크래치패드에 .py 파일로 써서 실행했다(지난번과 같은 함정).
