## 0. 원격 머지 뒤 로컬 반영

GitHub에서 머지하면 로컬은 모른다. `git fetch` 후 `master..origin/master`와
`origin/master..master`를 둘 다 보고, 로컬 쪽이 비어 있으며 작업 트리도 깨끗한 것을
확인한 뒤 `git pull --ff-only`로 받았다. `--ff-only`를 붙이면 예상과 달리 갈라져
있을 때 머지 커밋을 몰래 만들지 않고 멈춘다.

받은 뒤 바로 확인한 것 세 가지:

- **빌드·테스트** — 839 → 874개, 전부 통과.
- **공개 저장소에 로컬 경로가 들어오지 않았는지** — 새 파일(`archive.rs`,
  `filter.rs`)의 경로 문자열은 전부 테스트 임시 파일이었다.
- **PR이 문서까지 바꿨는지** — 바꿨다. 기여자가 **자기 포크용으로** 쓴 README
  상단 안내("이 저장소는 vuski/vwEditor의 포크입니다")가 PR에 섞여 원본에
  들어왔다. 원본 저장소가 자기를 포크라고 소개하는 상태가 된다. PR을 받을 때는
  코드만이 아니라 문서 변경도 읽어야 한다.

## 1. 그대로 둔 것

필터의 뼈대는 잘 짜여 있었다. 그래서 구조는 건드리지 않았다.

- 뷰 모드는 mmap 위에서 백그라운드 스레드 + rayon 청크(64K행) 병렬, 편집 모드는
  같은 로직의 동기 버전. 정렬(`sort.rs`)의 `SortJob` 패턴을 그대로 따랐다.
- 고유값 목록은 5,000개를 넘으면 해시맵에 새 키를 더 넣지 않고 HyperLogLog
  (2^14 레지스터, 16KB, 표준오차 약 0.8%)로 개수만 근사한다. ID처럼 전부 다른
  컬럼에서도 메모리가 고정된다. 체크박스는 1,000개까지만 그린다(가상 스크롤이
  없어 매 프레임 전부 다시 그리기 때문).
- 필터와 정렬을 함께 쓰면 필터 결과 안에서만 정렬한다. 화면은 `doc.filter`
  하나를 통해서만 그려져서 렌더 쪽은 바뀔 게 없다.

## 2. 필터 스캔이 행마다 `String`을 만들었다

PR의 스캔은 조건 하나를 검사할 때마다 셀 값을 `String`으로 만들고, "포함" 조건이면
`to_lowercase()`로 한 번 더 만들었다. 병렬이긴 해도 수억 행이면 할당이 스캔 비용을
지배한다.

**셀 값을 빌려서 비교하도록 바꿨다.**

- `row_field`가 `Cow<'a, str>`을 돌려준다. UTF-8이면 mmap 슬라이스를 그대로
  빌린다. 할당하는 경우는 셋뿐이다: 따옴표 안에 `""` 이스케이프가 있는 셀,
  잘못된 UTF-8(lossy), CP949/UTF-16(디코딩 자체가 새 버퍼를 요구).
- 바깥 따옴표 벗기기(`unquote`)도 `""`가 없으면 슬라이스만 좁힌다.
- "포함" 비교는 찾기 기능이 이미 쓰는 `find::find_ci_ascii`(memchr 기반, ASCII만
  대소문자 접기)로 바꿨다. 두 기능이 같은 입력에 같은 행을 잡게 되는 효과도 있다.
  대신 비ASCII 대소문자(예: `Ä`/`ä`)는 이제 구분한다 — 찾기와 같은 규칙이다.
- 체크박스 집합 조회는 `HashSet<String>::contains(&str)`로 한다.
- 고유값 카운트(`capped_bump`)도 `&str`로 받아 **처음 보는 값일 때만**
  `String`을 만든다. 값이 반복되는 보통의 컬럼이면 스캔 전체의 할당 수가 고유값
  수와 같다.

실측(1,000만 행 / 339MB CSV, release, 캐시된 상태):

| 조건 | 시간 |
|---|---|
| 포함 검색 1개 | 64ms |
| 숫자 범위 `>= 9000` | 92ms |
| 포함 + 숫자 범위 | 64ms |
| 체크박스 2개 값 | 60ms |
| 고유값 추출(10종) | 64ms |
| 고유값 추출(전부 다름 → HLL) | 77ms |

행당 6~9ns. 재현은 `filter.rs`의 `perf_filter_scan`(`#[ignore]`)으로 한다:

```powershell
$env:TV_PERF_FILE = "...\big.csv"
cargo test --release perf_filter_scan -- --ignored --nocapture
```

## 3. 숫자 범위 조건

`ColumnFilter`에 `min`/`max: Option<f64>`를 더했다. 필터 창에는 `최소 ~ 최대`
입력란 두 칸을 둔다. 연산자 드롭다운(`>`, `>=`, …) + 값 하나 방식도 있었지만,
두 칸이면 "이상/이하/사이/같음"이 한 UI로 되므로 이쪽을 골랐다.

- 경계 포함. 한쪽만 적으면 이상/이하, 같은 값을 적으면 등호.
- 셀은 스캔 중 그 자리에서 `&str → f64`로 파싱한다. 규칙은 숫자 정렬
  (`sort::number_key`)과 같다: 앞뒤 공백 제거 후 `parse::<f64>`.
- 숫자로 읽히지 않는 셀(빈 값, 문자)은 **통과하지 못한다**.
- `NaN`은 따로 막았다. `NaN`은 어떤 비교도 거짓이라, 막지 않으면 `x < min`도
  `x > max`도 거짓이 되어 범위 조건을 **통과해 버린다**.
- 입력란은 `String`으로 들고 있다가 Apply에서 파싱한다. 타이핑 도중의 `-`나
  `1.` 같은 미완성 입력을 그대로 둬야 하기 때문이다.

## 4. 버려진 스캔이 끝까지 돌았다

`recompute_view`는 새 작업을 시작하면서 `doc.filter_job = None`으로 옛 핸들을
버렸다. 그런데 핸들을 버려도 스레드는 멈추지 않는다. 큰 파일에서 Apply를 연달아
누르면 전체 스캔 여러 개가 동시에 돌며 CPU를 나눠 썼다. 정렬(`SortJob`)도 같은
구조였다.

**취소 통로를 progress 콜백에 겸했다.** 콜백 타입을 `Fn(usize)`에서
`Fn(usize) -> bool`로 바꾸고, `false`를 돌려주면 남은 청크를 건너뛴다. 별도
`cancel` 인자를 추가하지 않은 이유는 테스트 쪽 호출이 수십 곳인데 전부 `None`을
넘기고 있어서, 이 방식이면 손댈 곳이 없기 때문이다.

- 확인은 **청크 경계에서만** 한다. 행마다 원자값을 읽으면 hot loop에 부담이고,
  청크(64K행)는 수십 ms면 지나간다.
- 작업 핸들 세 가지(`SortJob`, `FilterJob`, `DistinctJob`)에 `Drop`을 붙여
  버려질 때 플래그를 세운다. `join`은 하지 않는다 — UI 스레드에서 드롭되므로
  스캔이 끝날 때까지 화면이 멈추면 안 된다.
- 취소된 스캔은 부분 결과도 돌려주지 않는다(빈 결과). 필터 뒤 정렬 단계도 취소
  플래그를 먼저 본다.

## 5. 세로 스크롤바가 표 내용 끝에 붙었다

PR #1은 `TableBuilder`를 `ScrollArea::horizontal`로 감쌌다. `TableBuilder`
(egui_extras 0.28)는 안쪽에서 세로 전용 `ScrollArea`를 만들고 가로는 지원하지
않으므로, 가로를 바깥에 한 겹 씌운 것은 맞는 판단이었다. 문제는 세로 스크롤바가
**안쪽** 영역에 속해서 표 내용의 오른쪽 끝에 붙는다는 점이다. 컬럼이 많으면
가로로 끝까지 밀어야만 세로 스크롤바가 보였다.

바깥을 양방향 스크롤로 바꾸는 방법은 쓸 수 없다. `TableBuilder`는 헤더를 세로
스크롤 밖에 두므로, 바깥이 세로로 움직이면 헤더가 같이 올라간다.

그래서 안쪽 스크롤바는 숨기고(`ScrollBarVisibility::AlwaysHidden`), 창 오른쪽에
세로 스크롤바를 **직접 그려** 안쪽 `ScrollArea`의 상태를 읽고 쓴다
(`egui::scroll_area::State::load/store`는 공개 API다). 휠, Page Up/Down, 찾기
점프는 안쪽이 그대로 처리하고, 새 스크롤바는 엄지 드래그와 트랙 클릭만 맡는다.

이 방식은 **안쪽 `ScrollArea`의 id를 우리가 맞혀야** 성립한다. egui_extras는
id_source 없이 `ScrollArea`를 만들고, 그러면 egui는
`ui.make_persistent_id(Id::new("scroll_area"))`를 쓴다. 이 규칙을
`table_scroll_area_id`에 적어 두고, 실제 `TableBuilder`를 한 프레임 돌려 그 id로
상태가 읽히는지 확인하는 테스트(`table_scroll_area_id_matches_egui_extras`)를
넣었다. 크레이트를 올려 규칙이 바뀌면 스크롤바가 조용히 안 그려지는데, 이
테스트가 유일한 경보다.

## 6. zip 열기를 뺐다

zip 안 CSV는 mmap할 수 없으므로 PR은 압축 해제본을 `read_to_end`로 통째로
메모리에 올렸다. 압축을 풀면 수 GB가 되는 파일이면 그만큼 램을 쓰고, 다 풀 때까지
화면이 멈춘다. 파일 전체를 읽지 않는다는 이 프로그램의 원칙과 맞지 않아서 기능과
`zip` 의존성을 함께 걷어냈다.

## 작업 중 걸린 것

- **CRLF.** 소스가 CRLF라서 Python으로 여러 줄 치환을 할 때 `\n` 기준 문자열이
  하나도 안 맞았다. 읽을 때 CRLF → LF로 바꾸고, 쓸 때 원래 개행으로 되돌리는
  래퍼(`rw`)를 쓰게 됐다.
- **필드 추가의 파급.** `ColumnFilter`에 필드를 더하자 테스트의 구조체 리터럴
  12곳이 컴파일 에러가 났다. 새 테스트는 `..Default::default()`로 썼다.
